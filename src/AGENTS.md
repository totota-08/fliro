# AGENTS.md — Git操作エージェント仕様  
> このファイルは、Codex エージェント（または同等の AI コーディングエージェント）に対し、Git／リポジトリ操作を含むワークフローを安全かつ一貫して実行させるためのガイドラインです。

## 1. 概要  
このプロジェクトでは、AI エージェントが以下のような Git操作を含むワークフローを自動、準自動で行うことを許可します：  
- 新規ブランチの作成 (`git branch`, `git switch -c`)  
- 変更のステージング／コミット (`git add`, `git commit`)  
- リモートへのプッシュ (`git push`)  
- プルリクエスト（PR）の作成／マージ（GitHub CLI 等を通じて）  
- 必要に応じてリベース／マージ操作、コンフリクト解消支援  

ただし、以下の **権限レベル**と **ガードレール**を設け、誤操作やリスクを最小化します。

## 2. 権限レベル  
以下の３段階レベルを定義します：

| レベル | コマンド実行範囲 | 用途 |
|--------|------------------|------|
| **Suggest / Read-Only** | リポジトリの読み込み、diff表示、ブランチ・コミット提案まで。Git操作自体はエージェントから実行しない。 | 初期検証、レビュー支援、学習目的 |
| **Auto-Edit** | エージェントが `git add/commit` 等を実行可能。が、プッシュ・PR作成・マージはエージェントが提案／人間が承認。 | 開発効率化、コード編集支援 |
| **Full-Auto** | エージェントがブランチ作成・コミット・プッシュ・PR作成・マージまで自動実行。 | 信頼できる環境・成熟チーム向け。慎重に運用。 |  

## 3. Git運用ポリシー  
エージェントに対して以下の運用ルールを明記します：

- ブランチ命名規則：`feature/`、`bugfix/`、`hotfix/` などをプレフィックスとし、識別しやすい名前にする。  
  例： `feature/ユーザ登録-バリデーション改修`  
- コミットメッセージ：Conventional Commits 様式を推奨。  
  例： `feat(auth): add email validation for signup`  
- PR作成時：  
  - タイトルは対応する Issue 番号および概要を含む。  
    例： `[#123] ユーザ登録バリデーションを追加`  
  - 説明には変更の背景、内容、影響範囲、テスト方法を記載。  
  - `Resolves #123` 等の記法を用いて GitHub Issue と紐付ける。  
- マージ前には必ずビルド／テストが通過している必要あり。エージェントはこのチェックを自律的に行うよう促される。  
- コンフリクト発生時：エージェントは自動解消提案を出し、人間レビューを必須とする。  
- プッシュ先およびマージ先ブランチ：通常 `develop` または `main`。変更先はプロジェクトのワークフローに従う。

## 4. ワークフローの例  
### (a) 新しい機能追加  
1. `develop` ブランチから、エージェントが `feature/…` ブランチを新規作成。  
2. 提案または実装を開始。必要に応じて変更をコミット。  
3. ビルド・テスト自動実行。  
4. テスト通過後、エージェントが PR を作成。人間がレビュー。  
5. レビュー承認後、マージ → `develop` あるいは `main` へ。  

### (b) バグ修正  
1. `bugfix/…` ブランチを作成。  
2. バグの再現・修正。コミット。  
3. ビルド＋テスト。  
4. PR 作成 → レビュー → マージ。

## 6. セキュリティ・リスク管理  
- Full-Auto モードではエージェントが任意のシェル／Git操作を行えるため、**信頼された環境・コードベース**でのみ使用。 :contentReference[oaicite:4]{index=4}  
- 機密情報・APIキー・データベース接続情報などが含まれるリポジトリでは、変更・コミット・プッシュ前に **人間による検証** を必須とする。  
- ログを定期的にモニタリングし、エージェントが意図しない操作をしていないかチェック。  
- コンフリクト発生・マージ失敗・テスト未通過等の際には、エージェントを停止し **手動介入**を可能に。

## 7. 制約・禁止事項  
- エージェントに対し、以下の操作を**禁止**：  
- `git push --force` の実行（あるいは強制マージ）  
- 既存のリリースタグの削除、改変  
- リポジトリ外（サブモジュール含む）の変更や、アクセス許可されていないリモート操作  
- コミット／PR内容に「機密／個人情報」が含まれていないか、事前チェックを行う。  
- エージェントが無限ループ／連続マージを行わないよう、**1タスクあたりの操作数制限**を設ける（例：一度の指示で最大50ファイル変更まで）。

## 9. モニタリング／レビュー体制  
- エージェント実行後の差分を必ず人間が確認するプロセスを設ける。  
- 自動コミット・PR作成済みのものについても **レビュー者**が担当し、マージ前にチェックリストを通す。  
- 実行ログ（コマンド実行内容・Git操作履歴）をアーカイブし、トレーサビリティを確保。

## 10. 継続運用のヒント  
- 最初は「Suggest / Read-Only」モードから運用を開始し、信頼できる挙動になった段階で「Auto-Edit」「Full-Auto」への移行を検討。  
- `AGENTS.md` を定期的に見直し、実際の開発に即して更新。 :contentReference[oaicite:5]{index=5}  
- テスト・CI／CDとの連携を強化し、エージェントが行った操作の安全網を構築。  
- チーム内でエージェント運用ポリシーを共有し、役割・責任を明確化する。
